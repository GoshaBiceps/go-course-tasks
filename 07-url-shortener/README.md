# URL Shortener

REST API сервис для сокращения длинных URL-адресов, разработанный на Go.

Проект реализован в рамках изучения Go Backend Development.

## Возможности

- Регистрация пользователей
- Авторизация с использованием JWT
- Создание коротких ссылок для авторизованных пользователей
- Перенаправление по коротким ссылкам
- Получение статистики переходов
- Кэширование с использованием Redis
- Хранение данных в PostgreSQL
- Запуск приложения через Docker Compose
- Unit-тестирование бизнес-логики и HTTP-обработчиков

## Технологии

- **Go** — основной язык разработки
- **net/http** — HTTP-сервер и маршрутизация
- **PostgreSQL 16** — хранение пользователей и ссылок
- **Redis 7** — кэширование
- **pgx** — работа с PostgreSQL
- **sqlc** — генерация Go-кода из SQL-запросов
- **JWT** — авторизация пользователей
- **Docker** — контейнеризация приложения
- **Docker Compose** — запуск нескольких сервисов

## Архитектура проекта

Приложение разделено на слои:

- **Handler** — обработка HTTP-запросов и формирование ответов
- **Service** — бизнес-логика приложения
- **Repository** — взаимодействие с хранилищем данных
- **Database** — подключение к PostgreSQL и сгенерированные SQL-запросы

Общая схема обработки запроса:

`HTTP → Handler → Service → Repository → PostgreSQL`

Redis используется для кэширования данных.

## Запуск проекта

### Требования

Для запуска проекта необходимы:

- Docker Desktop или Docker Engine
- Docker Compose

Для локального запуска через Docker устанавливать PostgreSQL и Redis отдельно не требуется.

### 1. Настройка окружения

Создайте файл `.env` на основе `.env.example`:

`cp .env.example .env`

Откройте `.env` и установите собственный случайный секрет для подписи JWT:

```dotenv
JWT_SECRET=your-own-long-random-secret
```

Файл `.env` используется только для локальных настроек и добавлен в `.gitignore`.

**Не используйте примерный секрет в production.**

### 2. Запуск PostgreSQL и Redis

В корневой директории проекта выполните:

`docker compose up -d postgres redis`

Docker скачает необходимые образы, если их ещё нет локально, создаст сеть и запустит контейнеры.

Для проверки состояния выполните:

`docker compose ps`

Перед применением миграций PostgreSQL должен иметь статус `healthy`.

### 3. Применение миграций

Перед первым запуском Go-приложения необходимо создать структуру базы данных.

SQL-миграции находятся в директории `migrations`.

Выполните их последовательно.

**Первая миграция — создание таблицы ссылок:**

`docker compose exec -T postgres psql -U postgres -d shortener -v ON_ERROR_STOP=1 < migrations/001_create_links.sql`

**Вторая миграция — создание таблицы пользователей:**

`docker compose exec -T postgres psql -U postgres -d shortener -v ON_ERROR_STOP=1 < migrations/002_create_users.sql`

**Третья миграция — добавление связи ссылок с пользователями:**

`docker compose exec -T postgres psql -U postgres -d shortener -v ON_ERROR_STOP=1 < migrations/003_add_user_id_to_links.sql`

Миграции выполняются вручную и предназначены для первоначальной подготовки базы данных. Повторно применять их к уже подготовленной базе без проверки не требуется.

### 4. Сборка и запуск Go-приложения

Выполните:

`docker compose up -d --build app`

Docker соберёт Go-приложение по инструкциям из `Dockerfile` и запустит его в отдельном контейнере.

Сервис будет доступен по адресу:

`http://localhost:8080`

### 5. Проверка состояния

Просмотр контейнеров:

`docker compose ps`

Просмотр логов приложения:

`docker compose logs app`

Просмотр логов с обновлением в реальном времени:

`docker compose logs -f app`

### 6. Остановка приложения

Остановить все контейнеры проекта:

`docker compose stop`

Повторно запустить остановленные контейнеры:

`docker compose start`

Данные PostgreSQL сохраняются в именованном Docker-томе `postgres_data` и не удаляются при обычной остановке контейнеров.

## API

### Регистрация пользователя

**POST** `/register`

Пример тела запроса:

```json
{
  "email": "user@example.com",
  "password": "Test12345!"
}
```

При успешной регистрации сервер возвращает:

- HTTP `201 Created`
- `user registered successfully`

### Авторизация пользователя

**POST** `/login`

Пример тела запроса:

```json
{
  "email": "user@example.com",
  "password": "Test12345!"
}
```

При успешной авторизации сервер возвращает HTTP `200 OK` и JWT-токен:

```json
{
  "token": "<JWT_TOKEN>"
}
```

Полученный JWT необходимо использовать для доступа к защищённым маршрутам.

### Создание короткой ссылки

**POST** `/shorten`

Требуется авторизация.

Заголовки запроса:

`Content-Type: application/json`

`Authorization: Bearer <JWT_TOKEN>`

Пример тела запроса:

```json
{
  "url": "https://go.dev"
}
```

При успешном создании сервер возвращает HTTP `201 Created` и короткую ссылку:

```json
{
  "short_url": "http://localhost:8080/abc123"
}
```

`abc123` — пример короткого кода. Реальное значение генерируется приложением.

### Переход по короткой ссылке

**GET** `/{code}`

Пример:

`GET http://localhost:8080/abc123`

Обработчик ищет исходный URL по короткому коду и выполняет перенаправление.

### Статистика ссылки

**GET** `/stats/{code}`

Маршрут предназначен для получения статистики короткой ссылки, включая информацию о переходах.

## Тестирование

Для запуска всех Go-тестов:

`go test ./...`

Для запуска тестов с подсчётом покрытия:

`go test ./... -coverprofile=coverage.out`

`go tool cover -func=coverage.out`

`go tool cover -html=coverage.out`

## Конфигурация

Приложение использует переменные окружения.

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Строка подключения к PostgreSQL |
| `REDIS_ADDR` | Адрес сервера Redis |
| `HTTP_PORT` | Порт HTTP-сервера |
| `BASE_URL` | Базовый адрес для формирования коротких ссылок |
| `JWT_SECRET` | Секрет для подписи и проверки JWT |

Параметры подключения к PostgreSQL и Redis для локального запуска заданы в `docker-compose.yml`.

Значение `JWT_SECRET` передаётся из файла `.env`.

## Docker

Проект использует три отдельных контейнера:

1. **app** — Go Backend API
2. **postgres** — PostgreSQL 16
3. **redis** — Redis 7

Контейнеры объединены внутренней сетью Docker Compose.

Для сборки Go-приложения используется многоэтапный `Dockerfile`: исходный код компилируется в отдельном этапе сборки, после чего исполняемый файл переносится в минимальный итоговый образ.
